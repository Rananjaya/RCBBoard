# RCBBoard 5.1.1 Google Play declarations

Prepared 26 November 2026 from the 5.1.1 source tree. This is a Play Console preparation note, not a submission or a claim that Google has accepted the declarations.

## Data Safety review

The manifest has no `INTERNET` permission. The application handles typed text, learned words, clipboard history, emoji history, optional personal-dictionary words and (when enabled) contact names locally. The source has no advertising, analytics or tracking integration. Google Play's Data Safety guidance says on-device access and processing that is not sent off-device does not need to be disclosed as collected data. On that evidence, the expected answers for app-controlled data are **no collection** and **no sharing**.

Before submitting the form, check the exact dependency inventory in the production variant and confirm that the Play Console form treats Android system Auto Backup as system-managed backup rather than collection by this app. `android:allowBackup="true"`; Android may transfer app data, which can include clipboard history and the optional contact-name dictionary, to the user's backup provider. This behavior is described in `PRIVACY_POLICY.md`. Do not omit or misstate this behavior in the policy even if the Data Safety answer remains no collection.

Other relevant answers, if the Console asks:

- Account creation: none.
- Data deletion request: no developer-held account data; users can clear app storage/uninstall and manage Android backups with their backup provider.
- Encryption in transit: not applicable to app traffic; the app has no network permission.
- Data processed: typed text and personal content are processed only on-device by the keyboard. Optional contact names are processed on-device after opt-in and permission grant.

Google's review of the submitted form is authoritative; these answers must be checked against the final dependency and Play Console forms before submission.

## Contacts permission declaration

The app requests `READ_CONTACTS` for the optional **Look up contact names** keyboard feature. The feature reads names on-device and builds suggestions/autocorrections while the user types. This is a keyboard autocomplete use case expressly covered in Google's Contacts Permission guidance. A one-time Contact Picker selection cannot provide the full address book needed for ongoing name suggestions across text fields. The feature is optional, permission-gated and can be disabled in Text correction settings.

Suggested Play Console declaration:

> Auto-Correct/Auto-Complete. RCBBoard uses contact display names only to offer local word suggestions and autocorrection as the user types. This is an optional keyboard feature, disabled until the user enables it and grants Contacts permission. It reads names on the device and does not transmit them. A Contact Picker provides only user-selected entries and cannot supply the changing set of all names required for live keyboard suggestions across fields; repeatedly selecting contacts is not equivalent to system-wide autocomplete. Users can turn the feature off or revoke permission at any time.

Target SDK 37 makes the app subject to the new declaration process. Google says developers are prompted in Play Console from September 2026 and enforcement for target API 37 begins 27 January 2027. Complete the declaration and receive the required approval before that deadline; it is a manual Play Console action.
